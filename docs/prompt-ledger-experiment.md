# 澄清前缀账本观察实验

开始记录日期：2026-10-12。状态：观察中。复核日期由用户在积累真实澄清续跑样本后手动指定；当前未设定自动期限，也不会自动删除机制。复核时应记录日期、样本时间范围和决定。

## 冻结范围与不变量

`src/prompt-ledger.mjs` 独立持有澄清续跑、三份内存账本和发送文本记录。`Bridge` 只提供任务、会话、提交及状态更新的接口。此次抽离保留原有回退顺序：可信任务记录 → 同任务/会话/generation 的内存发送文本 → 持久发送缓冲 → 契约与已提交澄清历史。准备、提交、回滚及提交标记的原有判定保持不变。

观察期间冻结回退链的功能扩展，不增加新的来源、回退条件或文本拼接逻辑。以后保留或删除实验时，以模块为调整边界，并继续满足：

- 未提交答案必须回滚，不能留在已提交澄清历史中。
- 已发送事实不能被未发送意图覆盖；恢复后线上文本仍须保留先前已发送答案，排除未发送答案。

这些是正确性要求，不能等待实验结果再保证。测试使用 fake ACP 独立记录收到的文本，与桥的记录交叉核对。

## 统计入口

```sh
node src/cli.mjs inspect --state-root <状态目录>
```

输出的 `promptLedger` 包含四个事件计数：`prefix_appended`、`prefix_diverged`、`prefix_stability_unverified`、`last_prompt_text_not_recorded`；另有 `baseSources`、`reasons`（包括 `base_unavailable`）、`persistedHistoryIncomplete` 标志出现次数、首末事件时间和统计文件读取问题。

事件保存在同一状态目录的 `prompt-ledger-events.jsonl`，新建文件权限为 0600；只保留事件类型、任务 id、序号、基底来源及诊断标志，不新增保存提示正文。计数跨桥重启保留，不回填旧版控制台日志，也不自动清空。统计文件不存在时 `present=false`，表示尚未收集事件。损坏行单独计入 `malformedLines`，其余有效事件继续统计；读取失败报告 `readProblem`，不能把此时的零值解释为没有发生事件。

统计写入失败不会改变任务执行或回退选择，会向原日志渠道报告 `prompt_ledger_event_not_recorded`。出现这类诊断时，计数可能不完整，应保留原日志一起复核。

`prefix_*` 在准备续跑文本时产生，可能对应后来未提交的答案。计数不是已发送轮次数，也不是缓存命中率，更不能单独证明 DSH 的上下文组装行为。`persistedHistoryIncomplete` 统计的是带该标志的事件次数，不是不同故障或成功救场次数。复盘必须结合任务提交记录、恢复前后文本以及实际 worker 证据。

## 用户手动复核的判据

1. 真实样本中 `prefix_appended` 占绝对多数，`prefix_diverged` 和 `base_unavailable` 从未出现，且证据支持回退链未承担恢复工作：考虑将回退链降级为纯日志记录。
2. 不完整持久历史相关路径真实救过场：按基底来源区分内存回退与重启后的持久发送缓冲恢复，记录具体案例，再考虑正式化机制并补充文档。重启前内存不跨进程保存，不能把重启后的恢复直接归因于旧进程内存。
3. 证据不足以区分：延长观察期，保持结构和功能冻结。

以上均需用户决定，不由计数阈值自动触发。真实模型冒烟仍须逐次授权。原生 Windows/macOS 官方 Desktop、ARM64、活跃 WebUI 会话共享继续按未验证记录；本实验不改变发布语种或 npm 的 `private: true`。

## 本批验收记录（2026-10-12）

188 项离线回归、74 项单元测试与 fake 冒烟通过。两条不变量在抽离前与抽离后均通过；原澄清及发送记录语句的机械比对一致。Linux Desktop 上独立真实模型冒烟通过，包含一次真实澄清续跑；退出后由新进程读取到一次 `prefix_appended`（来源为 `persisted`），其余三个指定事件计数为零，发送记录与持久文本缓冲一致。

这只是本批验收样本，不是长期观察结论；没有据此删除或扩展回退链。取消场景没有工具调用，不能据此宣称运行中工具中断已经验证。原始报告与测试状态仅保存在本机忽略目录中。
